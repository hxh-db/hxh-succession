# データ管理ルール

このフォルダでは、原作で確認できる事実と表示上の推定を分離する。

## 出典の優先順位

矛盾がある場合は、次の順で採用する。

1. ユーザーから提供された原作ページ画像
2. 第410話以前の単行本で確認できる情報
3. 第411話以降の本誌掲載時の表記
4. ユーザーの確認メモ・転記
5. 二次資料・考察

本誌掲載分は単行本化前のため、誤字・曜日・相対時刻の不整合があり得る。確認メモにも転記ミスの可能性があるため、画像未確認の情報は `notes` に根拠と確度を残す。下位の出典が上位の出典と矛盾する場合、上位の情報を採用し、元の表記は監査用の注記として保存する。

## 共通ルール

- 人物は1人につき1つの `id` を持つ。同一人物を役職や登場時点ごとに分割しない。
- 不明な値は `null` とする。「おそらく」などの推測を確定フィールドへ入れない。
- 仮称は名前に `（仮称）` を付け、原作で名前が判明した時点で同じIDのまま更新する。
- 氏名不明の人物を人物一覧に載せるのは、原作画像で個別の顔・姿を識別でき、既存人物との重複を確認した場合に限る。人数だけが分かる場合はイベントの人数情報として記録し、人物一覧に新規登録しない。
- 匿名の個別確認済み人物には `is_placeholder: true`、`identity_status: unnamed_confirmed`、初出話 `source_chapter` を付ける。過去に人数だけを根拠に作られたレコードは `count_only_characters.json` に列挙し、履歴参照を残しつつ人物一覧から除外する。
- 名前・実在の裏付けを原作で確認できない既存レコードには `verification_status: unverified` を付け、根拠を確認するまで人物一覧から除外する。削除や別人への画像割当てはしない。
- 王子ごとの `camp` は一人の王子の陣営を示す。別王子との共闘は `alliances.json` に記録し、初期配置や陣営人数を合算しない。第10王子と第11王子は別陣営、第六王妃セイコは母自身の陣営として扱う。
- `notes` には事実と考察を混在させない。未確定情報には明示的に「未確定」と記載する。
- 表示名では王族の「＝ホイコーロ」を省略するが、原データの正式名は維持する。

## characters.json

- `affiliation`: 制度上・組織上の所属（ハンター協会、第7王妃所属兵など）。
- `camp`: 現在支持・護衛している陣営。
- `room`: 最新確認時点の配置先。初期配置しか分からない場合は `notes` にその旨を記載する。
- `current_assignment`: 最新確認時点の任務。過去の配置・任務は `notes` と `events.json` に残し、状態変化だけを `status_log` に記す。
- `target`: 呪殺・監視・暗殺の対象、または従事先の王子。王子と確認できた場合だけ「第N王子氏名」と記す。所属元や一時的な訪問先からは補完しない。原則として現在の対象を記し、旧対象は `notes` と出来事に残す。過去の任務だけが記録される場合は `target_status: "過去"` を併記し、画面にも「当時」と表示する。
- `target_history`: 同じ任務で王子間を配置換えされたことが確認できる場合に限り、過去の対象と終了話数を記す。カードでは過去→現在の順に表示する。
- `status`: 最新確認時点の状態。
- `children` / `parent_ids`: 原作で確定した親子関係のみを登録する。
- `public_mother_id` と `reported_biological_mother_id`: 公的な母と手紙に実母と記された人物を区別する。後者は血縁確定の `parent_ids` には入れず、表示にも未検証と明記する。
- `suggested_father_id` / `suggested_child_id`: チョウライとオニオールのように親子関係が示唆されるが確定していない場合に使用する。`known_half_sibling_ids` は確認済みの異母兄弟を表す。

## character_tags.json（試行）

- 人物一覧で横断検索するための表示タグ。`definitions` はタグID・分類・表示名、`assignments` は人物IDとタグIDの対応。
- 分類と短い任務タグは全員分の `type` / `mission` から表示・絞り込みできる。第1王子私設兵の所属タグは `affiliation` と `soldier_category` から一括生成し、監視・暗殺・従事の相手先タグは明示した `target` に限る。他の所属・護衛対象・家族などの追加タグは試行中。追加タグのない人物を「関係なし」と解釈しない。
- 画面上のタグは種類ごとの色と短い名前で示し、上部の一覧からも選べる。「関係王子」は広い関係の絞り込みで、護衛先・標的タグとは区別する。
- 念講習会の第1回・第2回参加者タグは出来事の参加者リストから生成する。講師クラピカと、第2回への参加を申し出ただけで受講未確認のスラッカは参加者タグに含めない。
- 人物カードの血縁・憑依・任務先の変化・死亡／殺害などの追加タグは「ネタバレ＋」に格納する。血縁は短い `血縁 → 相手＋相手` の並びで示し、未確定の相手にだけ `※推測` を添える。母子・異母兄弟など関係の種類は詳細に記す。血縁・状態・念講習会の横断絞り込みも別の折りたたみに入れる。
- `死亡` タグは現在の `status` が死亡で始まる人物に付ける。死亡記録に `killer` の人物IDが明記されている場合だけ `死亡 ← 加害者` を表示し、不明な場合は `死亡` のままとする。`殺害` タグは別人の `status_log[].killer` に人物IDが明記され、記録された状態が死亡の場合だけ付ける。推測や備考文の単語からは付けない。
- 人物詳細は備考の説明文とタイムラインを中心にし、所属・状態・任務などの項目表は重複するため表示しない。血縁関係の種類や能力など、表を外すと失われる補足だけ説明文に含める。
- 場所や移動時点はタグにしない。`room` と出来事の位置情報を別に扱う。既存の所在推定には、複数人物の出来事の場所を全員へ割り当てる問題が残るため、「現在地」としてカードに表示しない。
- 原作話数・履歴を付けて全面展開する前に、各タグの根拠と現在／過去の区別を再照合する。

## events.json

- `chapter`: 事実が描写・説明された話数。
- `day`: 原作で日付が確定できる場合のみ数値を入れる。
- `time_start` / `time_end`: 作中時刻が明示された場合のみ入れる。
- `is_estimate`: 出来事の内容自体が前後関係からの推測である場合に `true` とし、画面上で「推測」タグを付ける。時刻だけの推測は `time_estimate` と分ける。
- `room`: 単一の号室番号として扱える場合に使用する。王子居住区は `第1層 1001号室` の形式を基準とし、「エリア1」「第1王子の居室」などの別名は表示用データに使わない。
- `location`: 複数地点、移動、号室以外の場所に使用する。複数の王子居室にまたがる場合も、可能な限り `第1層 1013号室・1014号室` のように号室で記す。
- `description`: 原則として「誰が・何をしたか」を現在形で簡潔に記す。部屋を示す場合は人物名による呼称ではなく号室表記を使う。
- 画面上の日付補完は `script.js` の表示ロジックで行い、推定値を `day` に保存しない。
- 日付が確定している通常イベントには「日付確定」タグを出さず、日付タブと「○日目」の表示で示す。推測・暫定・日付不明だけを注意タグとして表示する。

## 情報源

- 公式公開状況は `sources.json` に記録する。
- 詳細な出来事は原作話数を最優先の根拠とする。
- 二次資料だけで追加した情報は、原作確認待ちとして `research_backlog.json` に残す。
