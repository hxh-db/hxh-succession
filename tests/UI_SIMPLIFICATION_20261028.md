# 検索画面とネタバレ表示範囲の整理

2026-10-28の後続ユーザー方針に基づく変更。以前の過去名簿の実装記録は当時の履歴として保持する。

- 通常検索の「名簿を調べる」「名簿の時点」、王妃所属兵の専用セレクトと重複ナビを撤去。王妃の所属兵は既存の所属タグ1つで選択し、検索・他のタグ・共有リンクと組み合わせる。
- 出航時230枠と第374話の配置・人数資料は基礎資料に保持。歴史的な根拠JSON、人物401件・出来事465件、履歴データを削除しない。
- 人物一覧・個別人物・人物索引・考察・調査資料に同じ「ネタバレ表示範囲」を設置。「基本情報のみ」「収録済み全情報（第420話まで）」の2択。後者の話数は公開JSONの最大収録話数から生成し、出版上の最新話とは呼ばない。既存の真偽値の保存設定と別タブ同期を維持する。
- 旧 `c_when` と保存済み履歴の時点条件を解除。制限付きの旧リンクは基本情報へ戻し、以前の全情報設定によって突然先の内容が見えるのを防ぐ。旧 `c_queen` は見える所属タグへ移す。共有リンクでは受け手の表示範囲を変更しない。
- 記事・資料の対象話数フィルタは、その項目全体の上限で絞る条件として説明し、サイト全体の表示範囲と区別する。

## 指定話数・コミックス対応を有効にしない理由

現在、`fact_history` は1人に2件、`nen_history` は3人に4件。41件の固定タグ定義には統一した開示話数がない。初出話数や状態変化の記録だけでは、各能力・血縁・資格・任務のすべての判明時点を保証できない。コミックスの巻と収録話数を範囲設定に結びつける専用台帳も未整備である。

次の段階は過去の人物像の完全再現ではなく、個々の情報の開示話数を根拠とともに整理し、検索・タグ・候補件数・人物詳細・出来事・直接リンクまで同じ範囲で制御すること。未確認の項目を「当時不明」と断定しない。対応していない選択肢は画面へ出さない。

## 検証の扱い

撤去した時点UIのブラウザ検査は、新しい仕様に基づく旧URL・履歴の移行、基本情報の保護、通常検索・所属タグ、基礎資料の230枠の検査へ置き換える。元の履歴計算・出典・230枠の単体検査は維持する。個人メモは隔離fixtureで検査し、実際の保存ファイルへ接続しない。検証結果は作業ログと最終報告に記録する。

公開用スナップショットの標準検査は57/57成功（Python単体80件を含む）。異なる全46本のブラウザ検査が最終的に成功。初回41/46から、移行案内の表示位置を修正し、撤去済みUIの期待値・モーダル内の選択子・非同期のURL更新待機を新仕様に合わせて修正して再検証した。基本情報の保護、PC／スマホ幅、旧URL・履歴、共有リンク、別タブ同期、私的に追加した話数で公開収録範囲の表示が増えないことも確認。初回の失敗ログは残している。
