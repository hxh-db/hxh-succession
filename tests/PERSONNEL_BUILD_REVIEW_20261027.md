# 名簿生成・人物分類の検査不一致の修正（2026-10-27）

## 原因と対応

- HA-U01の分類漏れは、先行する公開コミット `224bd36f` ですでに `face_reference` に分類済み。初期230枠への所属は未確認のまま維持する。
- 先行する人物追加後の `characters.json` は、名簿生成器が出力する「元レコード＋生成レコード」の順序とずれていた。公開済みの入力だけで再生成し、人物・属性は変えずに順序を同期した。依存するマニフェストとサイトマップも再生成した。
- WindowsのCRLFとLFの違いで、名簿・分類レポートの検査と入力ハッシュが変わっていた。両生成器の出力比較と分類レポートの入力ハッシュではCRLFをLFへ正規化する。空白・本文・JSONの内容の違いは引き続き検出する。
- 関連生成物の検査で、公開済みQ005索引の検索語と生成器の入力がずれていた。生成器の検索語を公開済み索引に同期し、検索できる語を維持した。記事本文・事実データは変更しない。

## 再発防止

`node tests/personnel-build.cjs` は個人メモを使わない一時フィクスチャで以下を検証する。

- HA-U01を生成レコードの後に置いても失われず、名簿と分類の再生成が2回目で完全一致する。
- 出航時230枠と顔資料の分類を維持し、HA-U01を初期名簿へ加算しない。
- LF・CRLF・混在環境で入力ハッシュが一致し、検査がファイルを書き換えない。
- 本文に直接表示されない入力変更・生成レポートの改変・HA-U01の分類削除をそれぞれ検出し、失敗時も書き換えない。

このテストは標準の `node scripts/check-project.cjs` で自動的に実行される。
