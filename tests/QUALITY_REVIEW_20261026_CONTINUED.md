# 継続改善：メモの復旧・バックアップ・移動時の保持

2026-10-26。前回の品質改善に続き、実際に残っていた保存データ消失とエラー分離の問題を修正した。元の人物・出来事JSON、既存のステージ内容、個人メモファイルは変更していない。

その後の[出来事編集・同一項目の競合・参照検証の改善](QUALITY_REVIEW_20261026_EDITING.md)も参照。

## 今回の改善

### 再読み込みで未同期メモを捨てない

以前はPCファイルの全体の書出し時刻より古いブラウザ専用メモを除外していた。このため、PC保存が失敗した後に別ページのメモだけがPCへ保存されると、まだ必要なブラウザの控えまで消える。

全体の書出し時刻を削除の根拠にせず、項目ごとの更新日時・空にした記録・一括リセットの世代だけで統合するようにした。追加した出来事の控えも保持する。`draft-startup.cjs` は修正前に未同期メモの消失を再現し、修正後は保持・空欄化・リセットの各条件を確認した。

### バックアップを取得直前の内容で作る

開いた時点のメモだけを書き出していた処理を、入力待ちの確定→保存処理の完了待ち→ブラウザ・PCの再読込→統合の順に変更した。別ページのメモや別ブラウザからPCへ保存されたメモも含む。復元時の上書き確認も最新の内容を読んでから行う。

読込中は処理中の表示を出し、取得後はメモ一覧と件数も同期する。バックアップの件数と古い一覧の件数が食い違ったままにならない。

PCの最新内容を取得できない場合も、このページとブラウザに残る内容をバックアップできる。ただしPCの最新内容を含められなかったことを明示する。確認できないPCメモを「存在しない」とは表示しない。一括リセットはPCの読込に失敗したら引き続き停止する。

### 壊れたメモと人物検索を分離する

ブラウザ保存が壊れたJSONだった場合や、メモの項目がnull／配列／不正な型になっていた場合、全体の初期化が止まるか、他の保存で元の内容が上書きされる経路があった。

読み込みと保存の入口で構造を検査する。壊れたデータは変更せず、人物検索・人物詳細は起動する。メモ変更・追加・復元・リセットは停止し、理由をメモ管理に表示する。ブラウザの元の文字列は「読み込めないブラウザデータを保存」でそのまま取り出せる。PCの壊れたファイルも残す。正常なメモでは復旧専用ボタンは表示しない。

読み込めなかったデータを「0件」「まだメモはありません」と表示せず、読み込めた分の件数と他は未確認であることを分ける。停止中のボタンも薄く表示し、利用できる復旧用の操作と区別する。

考察記事のメモも同じ構造検査を使い、読み込めない保存を空のデータとして上書きしない。自動修復やデータ削除は行わない。

### 入力直後のページ移動に備える

650msの自動保存待ちに再読み込みすると、タイマーが破棄され入力を失う場合があった。人物URLの再読み込みでは静的人物ページへ移る仕様も維持したうえで、一覧へ戻ると入力を復旧できるようにした。

未保存のメモがある場合は、移動前・ページを隠す時点で同期的にブラウザの控えを作る。控えも作れない場合は移動確認を出し、取り消すと入力欄を残す。未保存でない通常の画面には移動確認用のハンドラーを残さない。一括リセットによる意図した消去を古いページから復活させない。

考察記事では、遅れて完了した古い保存が新しい控えを上書きしないよう、保存要求時の内容と更新日時を固定した。トップ画面でも、古い保存完了で新しい入力に「保存しました」と表示しない。連続保存の最初が成功しても、後の保存が失敗した場合は未保存状態を保持する。

## 限界と区切り

ページを離れる通常の経路を対象とする。OS・ブラウザの強制終了、ストレージ自体の破損、実機iOS／Androidのライフサイクルは保証・検証していない。壊れたメモの修復は控えを確認してから別途行う。

今回再現できた復旧・バックアップ・移動時のデータ保持の問題を解消した。原作再照合と実機・他ブラウザの確認は継続課題。根拠なしの仕様変更や、効果を確認できない最適化には広げていない。
