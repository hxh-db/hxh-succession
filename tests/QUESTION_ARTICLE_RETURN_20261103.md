# 未解決事項から考察記事への往復（2026-11-03）

未解決事項の「根拠と考察を読む」を通常クリック／Enterで開く前に、元リンクと閲覧状態を元ページの履歴へ保存する。記事から戻る／進むで分類・スクロール・元のリンクへのフォーカスを復元し、次のTab操作をページ先頭からやり直さずに続けられる。

記事は従来どおり通常のリンクで開く。記事URLへ復帰情報を追加せず、Ctrlクリックなど別タブの標準操作も維持する。記事側で基本表示に切り替えた場合は、元ページの非表示内容を開かず、表示中の案内ボタンへフォーカスする。記事だけを直接開いた利用者に復帰先を追加しない。

`question-article-return-browser.cjs` で1280・390・320pxのクリック／Enter、戻る／進む、分類・位置・元リンク・次のTab、Ctrlクリック、基本表示の復帰を検査する。変更前のJavaScriptでは同じ検査が元リンクへのフォーカス復帰で失敗した。原作データは変更しない。

最終の固定内容で標準検査60/60・関連ブラウザ検査5/5に成功。原作データ、共有index、個人メモは保持した。

## ページ保持時の保存設定との同期

ページ保持を有効にした公開検証では、記事側で基本表示に変えてから戻ると、可視の案内ボタンへフォーカスが復帰しないケースを確認した。保持されたページではpopstateが発火せず、pageshowのpersisted=trueで復帰することをイベント記録で確認した。記事リンクへの復帰では再表示時も保存済み履歴の復元を呼び、復元開始時に保存された表示範囲を読み、保持された画面の古い範囲と異なる場合は同期してから復元する。人物カードなど別の操作先を再描画してフォーカスを失わないよう、再表示イベントの対象を記事リンクの履歴へ絞り、通常のカード見出しのフォーカス保持も検査する。

隔離テストにも、保存設定がbasicなのに保持された画面はallという状態を追加した。修正前はallのままで失敗することを確認した。通常の経路と同じ期待を保ち、本文非表示と可視の案内ボタンへの復帰を検査する。公開検証ではページ保持の有無を別々に確認する。

ページ保持への対応後も、固定した最終内容で標準検査60/60・関連ブラウザ検査5/5に成功した。記事以外の人物カードの見出しへフォーカスしている再表示では、その操作位置を保持する検査も通過した。
